# Мобильная игра: retention, A/B-тест акционных предложений и метрики события

Учебный проект (Karpov Courses, 2023). Три задачи продуктового аналитика мобильной игры: расчёт retention, анализ A/B-теста наборов акционных предложений и выбор метрик для оценки тематического события.

**Инструменты:** Python (pandas, seaborn, matplotlib, scipy, pingouin), бутстрап, критерий хи-квадрат.

## Данные
Данные получены в рамках курса и в репозиторий не включены.
- Регистрации: 1 000 000 пользователей. Входы в игру: 9 601 013 записей.
- A/B-тест: 404 770 пользователей, группы a (контроль) и b (тест), поле `revenue`.

Пропусков и дублей в данных нет.

## Задача 1. Retention
Написана функция `retention(reg, auth, start_date, end_date, days)`: строит когорты по дате регистрации и тепловую карту удержания по дням. На примере когорт февраля 2020 retention максимален на 5–7 день после регистрации, затем интерес снижается.

## Задача 2. A/B-тест акционных предложений
Платящих пользователей меньше 1% в обеих группах (1 928 из 202 103 в контроле, 1 805 из 202 667 в тесте).

| Метрика | Контроль (a) | Тест (b) | Результат |
| --- | --- | --- | --- |
| ARPU | 25,41 | 26,75 | различие не значимо (бутстрап, p ≈ 0,55) |
| ARPPU | 2 664 | 3 004 | различие не значимо (бутстрап, p ≈ 0,09) |
| Конверсия в покупку | 0,95% | 0,89% | в контроле выше, значимо (хи-квадрат, p ≈ 0,04) |

Распределения revenue отличаются от нормального, поэтому использованы бутстрап и хи-квадрат, а не t-тест.

**Вывод:** по результатам теста лучшим считается набор из контрольной группы (выше конверсия при отсутствии значимой разницы в доходе). Оговорка: в контрольной группе есть 123 платящих пользователя с тратами более 37 000, а у остальных до 1 000. Проверить, ошибка это или нет, по данным нельзя; расчёт сделан в предположении, что данные верны. В реальной работе я бы сначала выяснил причину.

## Задача 3. Метрики тематического события
Предложены метрики по трём группам: привлечение (конверсия в событие, retention), активность (длительность сессии, DAU, число пройденных уровней, число попыток, churn) и доход (ARPU, ARPPU). Для события с откатом на уровни назад добавлены метрики: число откатов по уровням, повторные попытки после отката, churn после отката.

## Ограничения
- Платящих пользователей меньше 1%, поэтому оценки дохода неустойчивы.
- Причина аномальных трат в контрольной группе не установлена.

## Как запустить
Нужны Python 3 и библиотеки pandas, seaborn, matplotlib, scipy, pingouin, tqdm. Положите файлы данных рядом с ноутбуком и выполните ячейки по порядку.
